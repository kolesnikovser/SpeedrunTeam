## 1. Введение

В современных условиях бурного развития индустрии киберспорта и гейминга, скоростное прохождение игр (спидраннинг) переросло из хобби в профессиональную дисциплину. Эффективная координация команд, фиксация результатов и отслеживание достижений требуют специализированных и отказоустойчивых веб-инструментов.

Целью данного проекта в рамках кейс-чемпионата **«SpeedrunTeam»** является разработка полнофункционального, высокопроизводительного и визуально привлекательного веб-приложения **SpeedrunTeam**. Программа позволяет автоматизировать учет игровых команд, регистрировать время прохождения игр с точностью до миллисекунд, осуществлять полный жизненный цикл данных (CRUD) и предоставлять пользователям интерактивный опыт взаимодействия на основе современных практик веб-дизайна.

---

## 2. Постановка задачи

В соответствии с техническими требованиями кейс-чемпионата, система должна реализовывать следующий функционал:

1. **База данных:** Организация реляционного хранилища для учета команд спидраннеров и записей их результатов с поддержкой связей и каскадного удаления зависимостей.
2. **Бэкенд:** Разработка REST API на платформе Node.js для выполнения CRUD-операций над командами и забегами.
3. **Фронтенд:** Создание адаптивного пользовательского интерфейса (Single Page Application) на React + TypeScript для управления сущностями.
4. **Контейнеризация:** Создание конфигурации Docker для быстрого деплоя всей системы.
5. **Качество кода:** Написание модульных тестов, интеграция линтеров кода (Prettier) и настройка автотестирования (CI/CD).

## 3. Архитектура и системное проектирование

Система построена по классической клиент-серверной архитектуре с интеграцией базы данных на уровне сервера:

```text
  [ Пользовательский Браузер ]
               │
      (HTTP / JSON API)
               │
               ▼
   [ Express-сервер (Node.js) ] ──(static)── [ React SPA Bundle ]
               │
        (Wasm bindings)
               │
               ▼
    [ SQLite DB (sql.js) ]
```

### 3.1 Схема и структура базы данных
Для переносимости базы данных без компиляции бинарных C++ аддонов на хост-системах используется SQLite на WebAssembly (`sql.js`). 

База данных содержит три таблицы, связанные внешними ключами с каскадным удалением:
- **`teams`:** содержит команды (`id` автоинкремент, `name` строка).
- **`runs`:** содержит результаты (`id` автоинкремент, `team_id` внешний ключ, `time` строка для хранения точного тайминга, `date` дата забега).

### 3.2 Спецификация API (Бэкенд)
Сервер Express предоставляет следующие эндпоинты REST API:

- **Команды (`/teams`):**
  - `GET /teams` — получить список всех команд.
  - `POST /teams` — создать новую команду `{ name }`.
  - `PUT /teams/:id` — изменить название команды `{ name }`.
  - `DELETE /teams/:id` — удалить команду и все связанные с ней результаты.
- **Записи забегов (`/runs`):**
  - `GET /runs` — получить список забегов с присоединенными названиями команд.
  - `POST /runs` — зафиксировать результат `{ team_id, time, date }`.
  - `PUT /runs/:id` — обновить запись забега `{ team_id, time, date }`.
  - `DELETE /runs/:id` — удалить запись результата.

### 3.3 Пользовательский интерфейс (Фронтенд)
Интерфейс представляет собой клиентское приложение на React 18, использующее `react-router-dom` для навигации. Состоит из четырех страниц:
1. **Главная (Home):** Презентационная панель с кнопками быстрого действия.
2. **Команды (Teams):** Управление списком команд и их добавление/редактирование.
3. **Записи забегов (Runs):** Выбор команды, ввод времени (`ЧЧ:ММ:СС.мм`), календари дат и просмотр таблицы лидеров.
4. **О проекте (About):** Интерактивная визитка с описанием архитектуры.

## 4. Разработка и реализация

### 4.1 Инициализация SQLite Wasm
В файле `src/db.js` настроена асинхронная сборка WASM-модуля SQLite с автоматическим сохранением состояния из оперативной памяти на диск:

```javascript
SQL = await initSqlJs({ locateFile: file => `node_modules/sql.js/dist/${file}` });
if (fs.existsSync(dbPath)) {
  const fileBuffer = fs.readFileSync(dbPath);
  db = new SQL.Database(fileBuffer);
} else {
  db = new SQL.Database();
  // Инициализация схем таблиц...
}
```

### 4.2 Маршруты Express REST API
В `src/server.js` настроено отдание статики и роутинг для SPA, предотвращающий падения при обновлении страниц пользователями:

```javascript
// SPA Fallback
app.get('*', (req, res) => {
  const indexPath = path.join(frontendPath, 'index.html');
  if (fs.existsSync(indexPath)) {
    res.sendFile(indexPath);
  } else {
    res.status(404).send('Фронтенд не собран.');
  }
});
```

### 4.3 Клиентские страницы React
В качестве примера реализации интерактивного UI, страница **Teams** отправляет запросы к REST API с помощью нативного `fetch` API, обеспечивая плавность за счет локального состояния React:

```typescript
const fetchTeams = async () => {
  const res = await fetch('/teams');
  const data = await res.json();
  setTeams(data);
};
```

## 6. Развертывание и контейнеризация

Для развертывания проекта в любых операционных системах создана конфигурация Docker. Использован двухэтапный (multi-stage) процесс сборки для минимизации размера итогового образа:

```dockerfile
# Этап 1: Сборка Vite React
FROM node:24-alpine AS frontend-builder
WORKDIR /app/frontend
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ ./
RUN npm run build

# Этап 2: Запуск Node.js сервера
FROM node:24-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY src/ ./src/
COPY --from=frontend-builder /app/frontend/dist ./frontend/dist
EXPOSE 3000
CMD ["node", "src/server.js"]
```

Запуск Docker-контейнера осуществляется одной простой командой:
```bash
docker compose up --build
```
